# 项目开发铁则

本文档是 `Agent-Memory` 项目的最高开发约束。所有后续开发、重构、测试、提交都必须遵循。

## 1. 文档优先

- 所有开发过程必须落到文档中。
- 新增能力前，先更新设计文档或开发日志。
- 修改既有设计时，必须同步更新对应文档。
- 文档至少包含：目标、方案、模块影响、验证方式、后续计划。

## 2. 阶段提交

- 每完成一块完整需求，必须自动提交一次 Git 记录。
- 提交信息应清晰表达本次完成的功能或设计。
- 不允许把多个无关需求混在同一次提交。

## 3. Go 文件头注释

所有 Go 文件头部必须包含注释，说明：

1. 文件简要说明
2. 实现原理
3. 如何使用
4. 注意事项
5. 与哪些模块交互

推荐格式：

```go
// 文件说明：...
// 实现原理：...
// 使用方式：...
// 注意事项：...
// 交互模块：...
```

## 4. 编码规范

- 使用 `gofmt` 格式化所有 Go 代码。
- 使用 Go Modules 管理依赖。
- 错误必须显式处理。
- 禁止使用 `panic` 处理普通业务错误。
- 对外导出的类型、函数、变量必须有注释。
- 每个模块应尽量保持职责单一。

## 5. 架构原则

- 核心能力通过接口隔离，避免绑定某个供应商。
- `Embedder` 和 `VectorStore` 必须可替换。
- 索引流程必须支持后续扩展为增量索引。
- 搜索结果必须保留代码位置，包括文件路径和行号。
- 大模型接入层不直接依赖存储实现。

## 6. 安全原则

- 不在代码中硬编码密钥。
- 配置从环境变量或配置文件读取。
- 不索引 `.env`、密钥文件、构建产物和依赖目录。
- 输出日志避免泄露 token、API key 等敏感信息。
